# Ручное развёртывание машин и пробников

## Когда разрешено

Любые установки и обновления машин Hikkari выполняет хаб. Ручная установка
разрешена **только по явной просьбе владельца**, например для восстановления
недоступного хаба. Удобство, отсутствие ключа или старая сборка разрешением не
считаются. Агент не читает и не вводит пароль: владелец передаёт его на stdin
команды хаба. Пароль не должен попадать в аргументы, историю, логи или БД.

Штатный путь для уже зарегистрированного слота:

```sh
ssh hikkari-main 'sudo docker exec -i hikkari-fleet-hub-1 /usr/local/bin/hub entry-vantage-adopt ru-eurodir 130.49.175.145' < /secure/path/password
```

`password` — принадлежащий владельцу файл с одной строкой; команду запускает
владелец. Последний аргумент команды хаба необязателен: SSH-пользователь
(по умолчанию `root`); другому пользователю нужен `sudo -n` без пароля.

Роль точки задаёт реестр хаба (`entry_vantages.in_russia`): точки в РФ получают
`ENTRY_PROBE_ROLE=all`, контрольные вне РФ — `stand`. У lv-main на hikkari-main
пустой `last_admission_poll_at` ожидаем: он измеряет только стенд. Для него
обновление подтверждается свежим опросом SHA в роли `stand`; для точек в РФ
нужен также свежий admission poll. Хаб не меняет контрольную точку на точку допуска.

Хаб регистрирует бокс без релеев, устанавливает собственный ключ, проверяет
повторный вход ключом, отключает парольный вход, устанавливает пробник и ждёт
его SHA и свежего опроса допуска до 5 минут. Повторный запуск использует тот же
бокс. Ошибка содержит шаг; её видно в задаче развёртывания и журнале хаба.

## Ручное восстановление по просьбе владельца

1. Зафиксировать явное разрешение владельца и целевой слот. Проверить адрес,
   архитектуру (`uname -m`), владельца сервера и существующие systemd-сервисы.
   Не размещать пробник на боксе с релеями. На общем сервере Nekko не менять
   его `nekko-entry-prober`: Hikkari использует отдельный
   `hikkari-entry-prober`, `/etc/hikkari-entry-prober/prober.env` и
   `/usr/local/bin/hikkari-entry-prober`.
2. Получить бинарь **из текущего образа хаба**:
   `/usr/local/share/nekko/relay/linux-<arch>/nekko-entry-prober`.
   Сверить `sha256sum` источника и загруженного `.new`. Сохранить текущий бинарь
   в `.old`, а env и unit — в резервные копии с доступом только root. Не
   заменять работающий файл через запись поверх: установить `.new` атомарным
   `mv` на той же файловой системе. При отсутствии туннельного движка получить
   `nekko-edge` из того же образа. Не собирать произвольную локальную версию.
3. Проверить env: адрес нужного хаба, токен именно этого слота и путь движка.
   Файл принадлежит root, права `0600`; токен не печатать. Перезагрузить unit
   через `systemctl daemon-reload`, перезапустить нужный сервис. Проверить
   `systemctl is-active`, журнал, SHA файла, обновление `prober_sha`,
   `prober_poll_at` и `last_admission_poll_at` в `entry_vantages`. Одна активность
   процесса не подтверждает работоспособность. Если за 5 минут опроса нет —
   восстановить `.old`, env и unit, перезапустить, установить причину.
4. **Отдать хабу**: владелец запускает `hub entry-vantage-adopt <slot> <IP>
   [ssh-user]` с паролем на stdin. Команда сама устанавливает ключ хаба;
   если он уже стоит, пароль не нужен. Проверить отсутствие релеев у бокса,
   привязку `entry_vantages.box`, свежий опрос и SHA текущего образа. Ручная
   установка без этого шага не завершена. После принятия машины все её
   обновления выполняются хабом.

## Автоматическое обновление и откат

При запуске нового образа хаб сначала последовательно обновляет пробники,
затем запускает раскатку релеев. Архитектуру и SHA установленного бинаря читает
по SSH с проверкой закреплённого ключа хоста. `DeployProber` сохраняет `.old`
и старый env, ставит сборку своего образа, обновляет токен и ждёт SHA нового
процесса и свежего опроса допуска. Ошибка запуска или отсутствие опроса за
5 минут возвращает бинарь, env и предыдущий хеш токена. Снимок хеша токена сохраняется в `entry_prober_deployments`, а `.old` и
старый env не перезаписываются при возобновлении после перезапуска хаба.
После подтверждения новой сборки снимок закрывается. Неудачная сборка
автоматически не повторяется; явный adopt/повторное развёртывание позволяет
проверить её после устранения причины. Ошибка, SHA и время последнего опроса
доступны в карточке точки обзора в разделе цензуры и в журнале хаба.

На сервере с обоими сервисами выбирается существующий
`hikkari-entry-prober`; старый `nekko-entry-prober` сохраняется на выделенных
Hikkari-машинах. Перед изменением проверяется `PROBE_INGEST_URL`: установка
другого хаба не перезаписывается. Парольный вход отключается на всей машине;
это должно соответствовать разрешению владельца на передачу сервера хабу.

## Резервный режим без SSH

Владелец разрешил SSH-ключ хаба на nekko-spb (07.11.2026); штатный путь для него —
тот же adopt. Режим ниже предназначен только для явно согласованного исключения.

Сборка пробника поддерживает самообновление через токен слота. Для установки
без SSH нужен systemd unit с `DynamicUser=yes`, `Restart=always`,
`StateDirectory=nekko-entry-prober` и
`Environment=ENTRY_PROBE_UPDATE_DIR=/var/lib/nekko-entry-prober`.
Root-владелец `/usr/local/bin/...` остаётся загрузчиком; обновления запускаются
из StateDirectory с правами DynamicUser. На общем сервере использовать
отдельные StateDirectory и путь Hikkari. Первичное включение — через хаб или
по явному разрешению на ручное восстановление с обязательной передачей хабу.

Каждые 30 секунд пробник сообщает SHA и архитектуру на `GET .../entry-probes/update`.
Хаб выдаёт SHA и размер своей сборки; только слоту без бокса разрешает
самообновление. Бинарь скачивается с `.../entry-probes/binary` с токеном, только
по HTTPS, без перенаправлений, с ограничением размера и проверкой SHA-256.
Старая сборка сохраняется в `.old`. Systemd перезапускает загрузчик; при падении
новой сборки или отсутствии подтверждённого опроса за 3 минуты загрузчик
возвращает старую. Неудачная SHA блокируется до новой сборки хаба.
Старая версия, не поддерживающая этот протокол, сама его получить не может:
её первоначально заменяет хаб после adopt.

## Первичный доступ существующим ключом владельца

Если у владельца уже есть SSH-доступ к машине, CLI `entry-vantage-adopt` может
временно использовать переданный `SSH_AUTH_SOCK`. Пароль в этом случае не нужен.
Сам хаб входит через SSH-agent владельца, добавляет свой публичный ключ и
обязательно повторно входит собственным ключом с закреплением того же ключа
хоста. Затем выполняется обычный adopt. Приватный ключ владельца не копируется
в хаб и не сохраняется. После принятия машины транспорт агента закрывается;
автоматическая раскатка никогда не использует агент владельца.

Сокет передаётся только на время явной CLI-команды через SSH Unix forwarding
в `/data` контейнера (права `0600`, владелец uid 1000). Нельзя открывать агент
по общедоступному TCP или оставлять его после установки ключа хаба. Этот путь
не обходит аутентификацию: машина должна принимать существующий ключ владельца.
